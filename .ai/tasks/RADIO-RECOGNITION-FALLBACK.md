Both the phone radio playlist chooser and Android Auto's configured Radio songs action now use a shared metadata-first resolver. Missing/generic metadata, a station name or no matching YouTube song triggers the existing recognition engine on decoded radio audio. A matching YouTube Music track is required; radio no longer falls back to an arbitrary unrelated first search result. Existing playlist destinations, duplicate checks and remote sync remain. Successful matches cache for ten seconds and requests serialize; failures do not cache, transitions invalidate matches, station changes reject stale results and manual offline mode blocks starting a lookup. Identifying feedback is shown; recognition failures return not found and cancellation propagates.

RadioAudioCapture is a pass-through processor before volume/EQ processing. It retains only the latest twelve seconds of radio PCM in memory, downmixes to mono, requires five seconds of audio and expires samples after five seconds without input. Station/format flush/reset/release clear capture; non-radio audio is not retained and no recording is written to disk. A newly started station can wait up to twelve seconds for a usable sample. Recognition runs on demand only when lookup needs the fallback, without microphone access, permissions or foreground microphone services, so it does not depend on hearing the speakers. Radio disables audio offload to keep PCM available; the user's preference is restored outside radio and handled on player recreation. Other sources pass audio unchanged. Reuses the engine from RECOGNITION-IMPROVE (Claude): fingerprint/resample/gain normalization and existing optional AudD/token settings. It does not alter microphone recognition status/history or add to the separate Recognised songs playlist.
